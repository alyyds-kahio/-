# 确认方式（必须遵守）

修改前必须先给出**具体方案**：精确到改哪个文件、加什么参数/开关、具体逻辑、默认值、行为变化、涉及的比例/数值。
不要用"可以吗 / OK吗 / 行不行"这种模糊确认——这种确认方式无效。
给出具体方案后，等用户确认再动手；每完成一步，先展示具体改动。

# 方法步骤（把功能做成 config 开关插件）

1. `src/config.py` 加开关常量，默认 False（不改变现有行为），注释写清含义
2. 目标函数加参数（默认 = 关），True 时走新逻辑；不改模型主体
3. 入口（`train.py` 等）从 config 读开关并传入，写进日志 / 实验记录
4. 新建/更新 `experiments/TRAINING_PLUGINS.md`（插件配置说明），每项按统一结构：
   `默认 / 位置 / 含义 / 怎么开(具体步骤) / 怎么关 / 开行为 / 关行为 / 验证`
5. smoke test：开关=False 回归原行为；开关=True 验证新逻辑生效（含具体数值）
6. 步骤完成后**自动更新相关 plan.md**（如 `OPTIMIZATION_PLAN.md` 的进度/方案章节）
7. 新增/更新实验记录文档；涉及数据划分等行为变化时，明确写出具体比例/数值

# 通用要求

- 低耦合、可开关、可回滚；False/关闭时与原行为完全一致
- 不删除历史实验 / checkpoint / 文档
- 改动范围最小，不顺手重构
